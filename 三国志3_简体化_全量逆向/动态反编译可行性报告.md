# 三国志3 HAN.16P 动态反编译（字符码→槽位）可行性验证报告

日期：2026-08-12 · 环境：DOSBox-X 2026.08.02（SDL1 64-bit，内置调试器）

## 结论：可行（已验证通过）

成功在游戏运行时抓取“字符码→字库槽位”映射，主菜单绘制过程被完整捕获，**7 个已知锚点全部与运行时行为一致**（验收标准为 ≥5 个）。同时确认了关键事实：**游戏正文使用自定义字符编码（非标准 BIG5），绘制时经“游戏码→线性查表→槽位→字形偏移”链路取字形**。

## 验证方法

1. **调试器通路**：用 `debugbox main.exe` 在入口断下；通过控制台自动输入命令（keybd_event 逐键输入）、Win32 `ReadConsoleOutput` 读取调试器界面、`MEMDUMPBIN`/`LOG` 把内存与指令流写入文件。全部打通。
2. **定位字库缓冲区**：内存搜索 HAN.16P 前 112 字节特征，命中常规内存 **0x64E4A**（与槽 57 字形偏移吻合）；绘制代码用 ES=64E5 段访问，槽位 n 的字形偏移 = n×28。
3. **发现运行时映射表**：字符查找函数（094F:4D80）以 2 字节步长线性扫描 DS:1A9C 起始的表（上限 2506，共 1333 项），命中即返回表索引（=字库槽位）。
4. **捕获绘制链**：对键盘读取下断点（`BPINT 16`）+ 向 BIOS 键盘缓冲区注入按键（`SM` 写 40:1E），用 `LOG` 记录按键处理与菜单绘制指令流；命中 6.5 万条指令（含寄存器与访存地址）。
5. **提取映射**：从指令流中恢复“槽位→游戏码”表，共 732 项（槽 0–731），连续无缺口。

## 关键发现

- **正文为自定义编码**：游戏码（如 開=A1E3、請=A7F8）与标准 BIG5（開=B67D、請=BDD0）不同；已提取的 732 项中与标准 BIG5 吻合率为 0%。游戏码保持某种自定义字符集顺序。
- **正文文本不直接存 BIG5**：主菜单等正文以“游戏码”或“槽位索引”形式存储，绘制时不出现标准 BIG5 码——这解释了此前静态提取字符表失败的原因（不是加密那么简单，而是编码本身不同）。
- **表结构与位置**：码→槽位表在游戏数据段 DS:1A9C（本次运行 DS=54E4），1333 项 × 2 字节 = 2666 字节，可由 `MEMDUMPBIN 54E4 1A9C A6A` 一次导出。
- **绘制函数**：查表 094F:4D80；字形复制 094F:7BDC（读 ES:BX 28 字节）；入口调用 094F:5298。

## 全量方案建议（下一步）

1. 用 `MEMDUMPBIN` 直接导出完整表（1333 项槽→游戏码），不依赖逐屏绘制。
2. 逆向“游戏码→汉字”解码：优先在姓名输入/输入法代码处抓取“键→码→字”映射，或定位 MAIN.EXE 中的字符集表；结合已知锚点校验。
3. 用解码结果生成完整 slot→汉字表，逐槽校验后重建字库（仍只改 HAN.16P，字节数不变）。
4. 若解码受阻，可用“已知文本 + 绘制顺序”逐屏累积锚点（本次已证明可行），但效率低于解码。
